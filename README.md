# Анализ базы данных колл-центра банка

## О проекте

Разбор базы данных звонков колл-центра банка: SQL-запросы к SQLite и статистическая проверка гипотез. Цель — найти тренды, аномалии и зоны роста продажной конверсии.

Проект сделан по тестовому заданию из трёх частей:

1. собрать SQL-запросом одну общую таблицу из всех таблиц базы;
2. посчитать количество успешных звонков, продажную конверсию и среднюю длительность успешного звонка;
3. найти тренды, зоны роста и аномалии и собрать выводы в Excel-дашборд.

## Структура проекта

*   `Анализ_БД_звонков_банка.ipynb` — Jupyter Notebook со всеми SQL-запросами, статистическими тестами и графиками. В начале — краткое резюме результатов.
*   `db_analysys.xlsx` — Excel-дашборд, который ноутбук собирает при каждом запуске:
    *   «Дашборд» — ключевые показатели, главные выводы и графики (конверсия по управлениям, часам, дням и продуктам, доля дозвона, использование продукта);
    *   «Аномалии» — найденные проблемы в данных с количеством и комментарием;
    *   «Регрессия» — отношения шансов для выходных, вечера и знаков зодиака;
    *   «Данные графиков» и детальные таблицы из разделов ноутбука.
*   `data.db` — база данных SQLite (≈16 МБ, не хранится в репозитории: ноутбук скачивает её с Google Drive при первом запуске).
*   `requirements.txt` — список зависимостей.

## Данные

89 174 звонка за август 2022 года по 50 000 задачам. Звонки делали 1 962 оператора из 52 групп и 45 управлений, продавались 4 продукта.

| Таблица | Содержимое |
|---|---|
| `call` | звонки: задача, очередь, оператор, время окончания, длительность (текстом, с запятой: `'19,46'`) |
| `action`, `result` | результат звонка: «Дозвон, Успешно», «Дозвон, Отказ», «Недозвон» и другие статусы |
| `product` | предложенный в звонке продукт и флаг «клиент начал пользоваться» (заполнен только у продаж) |
| `task` | задачи: этап, источник (GI, FW, CM), даты создания и окончания |
| `queue` | очереди |
| `emp_x_org_gr`, `group`, `mngmnt` | оператор → группа → управление |
| `horoscope` | знак зодиака оператора |

Каждая задача в базе связана хотя бы с одним звонком. Поэтому задачи, созданные задолго до августа, попадают в базу, только если по ним ещё звонили в августе.

## Ответы на задание 2

*   Звонков со статусом «Дозвон, Успешно» — **3 310**.
*   Продажная конверсия — 3 310 / (3 310 + 18 459) = **15,21%**.
*   Средняя длительность звонка «Дозвон, Успешно» — **110,18 с** (у «Дозвон, Отказ» — 112,49 с). Длительность хранится текстом с запятой, и `AVG` по такому тексту берёт только целую часть (получается 109,69 с), поэтому перед усреднением её нужно привести к числу.

## Основные выводы

1.  **Главная зона роста — управления.** Если 24 управления, у которых конверсия ниже средней (и не меньше 100 звонков с результатом), выйдут на среднюю, это около +640 продаж в месяц (+19% к 3 310).
2.  **Управления различаются по-настоящему.** Большинство управлений выходят за границы случайных колебаний вокруг средней конверсии (15,2%). Выше средней — Хирс (65%), Керс (50%), Ребус (38%), Шоколад (31%), Дирис (26%) и крупнейшее управление Чизан (17%); ниже — 21 управление. Высокая конверсия Керса держится на одной группе: у группы 17 — 69%, у группы 38 — 18%.
3.  **В выходные и вечером конверсия выше, но из-за того, кто работает, а не из-за времени.** В выходные конверсия 24,9% против 14,8% в будни, в 18–19 часов — 26–27% против 12–16% днём. Однако у одного и того же оператора разница в выходные и вечером незначима. Высокую конверсию дают операторы, которые работают в это время, поэтому перенос звонков на вечер сам по себе вряд ли поможет — полезнее разобраться, чем эти операторы отличаются.
4.  **Дозвон почти не зависит от времени.** Днём и ночью дозваиваются одинаково часто (43,3% и 44,6%), в выходные чуть чаще, чем в будни (46,2% против 43,2%).
5.  **Продукт 2 продаётся хуже остальных.** Конверсия: продукт 1 — 22,6%, 3 — 16,2%, 4 — 15,7%, 2 — 11,1%. С учётом управления, времени и источника задачи значимо отличается только продукт 2: шансы его продать на 38% ниже, чем продукт 1.
6.  **Около 60% клиентов начинают пользоваться купленным продуктом**, по продуктам доли почти одинаковы (56–61%), от дня недели продажи доля не зависит.
7.  **Длительность звонка не связана с его результатом.** Почти все звонки длятся от 0 до 210 секунд, конверсия по 30-секундным интервалам — от 13,5% до 16,3% без тенденции.
8.  **Знак зодиака не влияет на продажи.** Связь, заметная при подсчёте по звонкам, почти исчезает при проверке на уровне операторов: преимущество «Стрельцов» объясняется тем, что они чаще работают в сильных группах. Значимо ниже только конверсия «Тельцов». Скорее всего, это метка какой-то подгруппы операторов, тем более что распределение знаков неестественное (40% «Дев» и 16% «Стрельцов» при ожидаемых ~8% на знак).
9.  **В некоторых очередях от создания задачи до звонка проходит больше двух недель** (в «Очереди 2» — 32 дня), в других — меньше суток.

## Аномалии в данных

*   58 звонков со статусом «Дозвон, Успешно» имеют нулевую длительность, и все они у двух операторов: у cyanrser — 51 из 70 (при 70 успешных звонках из 70), у yrovibna — 7 из 7. Именно эти операторы возглавляют рейтинги конверсии.
*   У управления Вирс все 251 звонок закончились «Недозвоном»; у управления Вазан за месяц всего 3 звонка.
*   У всех 2 366 задач из источника CM не заполнен этап, и только у них.
*   У этапов 3, 4, 16, 17, 18, 20 и почти у всех задач этапа 6 нет даты окончания — скорее всего, это незавершённые этапы.
*   556 задач длятся дольше 62 дней (при медиане 6 дней), самая долгая создана в апреле 2021.
*   Всплески создания задач: 35 задач этапа 6 за 28 июля и до 719 задач этапа 23 в день 18–20 августа.
*   Флаг использования продукта стоит у 7 звонков без продажи и отсутствует у 792 из 3 310 продаж.

## Методика

*   Продажная конверсия = «Дозвон, Успешно» / («Дозвон, Успешно» + «Дозвон, Отказ»). Пороги для рейтингов считаются по звонкам с таким результатом: не меньше 20 для операторов и 100 для групп.
*   Для конверсий приведены 95% доверительные интервалы Уилсона; рейтинг операторов сортируется по нижней границе интервала.
*   Звонки одного оператора не независимы, поэтому связи проверяются на уровне операторов: перестановочными тестами, логистической регрессией с ошибками, кластеризованными по оператору, и условной логистической регрессией (сравнение внутри одного оператора).
*   Таблицы сопряжённости для хи-квадрата строятся из фактических количеств.

## Ограничения

*   Данные только за один месяц: у оператора в среднем около 11 звонков с результатом «Успешно» или «Отказ», поэтому рейтинги отдельных операторов шумные.
*   В базе нет характеристик клиентов и стажа операторов, поэтому причины различий между управлениями и операторами из данных не установить.

## Как запустить проект

Проверено на Python 3.11.

1.  **Клонируйте репозиторий.**
2.  **Установите зависимости** (лучше в отдельном виртуальном окружении):
    ```bash
    pip install -r requirements.txt
    ```
3.  **Запустите Jupyter** из папки репозитория и откройте `Анализ_БД_звонков_банка.ipynb`:
    ```bash
    jupyter notebook
    ```
4.  **Выполните все ячейки** (Kernel → Restart Kernel and Run All Cells). При первом запуске ноутбук скачает `data.db` в папку репозитория; если скачивание не удалось, скачайте файл вручную по ссылке из первой ячейки и положите рядом с ноутбуком.

База открывается только на чтение: промежуточные таблицы создаются как временные, поэтому `data.db` не меняется и ноутбук можно перезапускать сколько угодно раз. В конце ноутбук пересобирает `db_analysys.xlsx`.
